# Which creative workflows should become reusable skills?

Researched 11 October 2026, Asia/Manila. Project files were inspected read-only. This note records local evidence; it does not independently verify external facts in earlier research notes. No survey rows or personal response fields were copied.

## Answer

The reusable process is: collect references, extract their visual rules, choose a direction against product constraints, prove one representative piece, produce a coherent family, and deliver editable sources plus a browsable library. Naming and motion need separate workflows because their evaluation differs from still-image production.

Use a small suite organized by these jobs. Generated raster art, SVG, Canvas, shaders, and 3D geometry are production choices within the process. Read the owner's medium constraints before selecting tools.

The procedural-pets direction boards are evidence of an experiment, but later owner feedback rejects them. They are not a successful design template. That failure makes reference interpretation, playable proof, and meaningful acceptance criteria essential.

## Proposed skills

These are recommendations, not observed installed skills.

| Job | Output | Boundary |
| --- | --- | --- |
| Research creative references | Cited reference ledger and comparable directions | Builds on research; does not choose taste or copy subject matter |
| Set art direction | Versioned visual contract and acceptance criteria | Project authority usable across media |
| Prepare production prompts | Self-contained briefs from direction and destination | Uses imagegen for raster generation; preserves approved identity and technical constraints |
| Build procedural art | Runnable representative scene, seeded primitives, adjustable parameters | SVG/Canvas/shader/3D when code is required; full product work stays with existing implementation skills |
| Build an asset kit | Manifest, editable source, exports, contact sheets, catalog, rebuild instructions | Family consistency and reuse; no mandatory large asset count |
| Design motion and trailer beats | Timed storyboard, transitions, cues, scrub preview, export | Distinguishes interface feedback, gameplay feel, explainers, and music-led trailers |
| Brainstorm and screen names | Source transformations, spoken checks, shortlist, collision ledger | Product/character naming; code naming stays under concrete-naming |

Shared rules: verify contract freshness, separate style from subject, label evidence and inference, prove one meaningful slice before bulk production, and perform real visual or interaction review. Put those rules in one small reference to prevent copies drifting apart.

## Open Questions

- Music-led trailer research needs song/version verification, lyric locations, official trailer examples with timecodes, and an original beat map. Those facts were not researched here.
- Medium constraints vary by project: the procedural-pets handoff forbids generated images, while Gagambattle permits generated source art. A global skill must read the current brief rather than impose either rule everywhere.
